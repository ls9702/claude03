# 인생게임 (HTTP 턴제 멀티플레이) 구현 계획

## Context

닌텐도 스위치용 「인생게임 for Nintendo Switch」(타카라토미, 2023 / 한국어판 2025)를 모티브로,
브라우저에서 접속하는 HTTP 기반 턴제 보드게임 서버를 만든다.
저장소는 비어 있는 그린필드 상태이며, 서버는 라즈베리파이 4에서 단일 프로세스로 구동한다.

핵심 요구사항
- 최대 4인(접속 세션) / 최대 8캐릭터. 한 사람이 여러 캐릭터를 조종 가능 (A=1~4번, B=5~8번 식).
- 실시간 세션 공유: 한 명이 행동하면 모두의 화면이 자동 갱신.
- 게임 페이지(`/`)와 관리자 페이지(`/admin`) 분리.
- 스위치판 요소(4개 능력치, 직업 랭크업, 연애·결혼, 서브맵, 결과발표의 보물감정·특별상)를 1차부터 포함.
- **3D 그래픽 보드**(Three.js, 브라우저 렌더링), **사운드**(효과음·BGM), **모바일 반응형**.
- **캐릭터 커스터마이징**(원작처럼 파츠 조합) + **모든 이벤트에서 내 캐릭터가 등장하는 컷인 연출**.
- Opus/Sonnet 브레인스토밍으로 뽑은 **재미 요소**(남의 턴 참여, 플레이어 간 상호작용, 엔딩 서사)를 1차부터 포함.
- **한국풍 배경**으로 재해석(원작의 일본풍 요소를 한국 생활·문화로 치환).
- **그래픽 에셋은 이 프로젝트 안에서 Gemini 이미지 생성(Nano Banana)으로 제작**: 관리자 페이지의 “에셋 스튜디오”가 매니페스트대로 배경·캐릭터 레이어·아이콘·텍스처를 생성하고, 생성물은 저장소에 커밋해 라즈베리파이에 배포. 현재 목업(SVG·프리미티브)은 자리표시자일 뿐이며 실제 룩은 생성 에셋이 결정.
- 시대별 턴 수는 기본값을 두되 **관리자가 방 생성 시 시대별로 조절** 가능.
- 이후 사용자가 기능을 계속 추가할 수 있도록 룰 데이터를 JSON으로 분리(데이터 주도 설계).

사용자 결정 사항: Node.js + Express / SSE + HTTP POST / 관리자 1차 기능은 방 생성·설정·시작·종료.

## 아키텍처

```
Browser(게임, Three.js 3D) ──POST /api/rooms/:id/actions──▶ Express ──▶ game/engine (순수 리듀서)
                          ◀──SSE  /api/rooms/:id/events────┘      └──▶ store (메모리 + JSON 스냅샷)
Browser(관리자) ─ /admin (쿠키 인증) ─ POST /admin/api/rooms ...
```

- **Node.js 20 LTS + Express**, 프론트는 번들러 없는 순수 HTML/CSS/JS ES 모듈. 라즈베리파이는 정적 파일과 JSON만 서빙하고 3D 렌더링은 각 클라이언트 브라우저가 담당하므로 서버 부하 없음.
- **Three.js는 npm으로 받아 `public/vendor/`에 복사**(postinstall 스크립트). LAN 전용 환경에서도 CDN 없이 동작.
- **엔진은 순수 함수** `applyAction(state, action, rng) → { state, events }`. 시드 RNG 주입으로 테스트·재현 가능. 엔진은 그래픽·사운드를 전혀 모르고, `events`(예: `moved`, `moneyChanged`, `married`)만 발행 → 클라이언트가 이를 애니메이션·효과음으로 변환.
- **실시간**: 룸별 SSE 채널. 상태 변경마다 `state`(세션별 마스킹 스냅샷) + `events` push. `EventSource` 자동 재접속, 하트비트 15초.
- **신원**: 로그인 없음. 세션 토큰을 `localStorage`에 저장해 헤더로 전달. 관리자는 `ADMIN_PASSWORD` 환경변수 + 쿠키.
- **영속성**: 룸 상태는 메모리, 액션마다 `data/saves/<roomId>.json`에 디바운스 저장. 재시작 시 복원.
- **캐릭터 소유**: `character.ownerSessionId`. 액션은 “그 세션이 소유 + 지금 그 캐릭터의 결정 차례”일 때만 허용. CPU는 `owner: 'cpu'`.
- **가문(패밀리) 턴 순서**: 같은 세션이 소유한 캐릭터는 연속 턴으로 묶어 진행(A의 1~4번 → B의 5~8번). 한 사람이 여러 캐릭터를 조종할 때 대기 시간을 줄이고, 가문 내 송금·가문 합산 순위(“가문상”)를 제공. 관리자 설정으로 “캐릭터 번호 순”과 전환 가능.

## 도메인 모델 (요약)

```js
Room { id, code, status: 'lobby'|'playing'|'finished', config, players[], characters[], turn, log[], seed }
config { mode: 'lifetime'|'kids'|'adult', eraTurns: { baby, elem, middle, high, young, middle_age, senior },
         maxCharacters: ≤8, startingMoney, allowCpu }
Player { sessionId, name, connected, lastSeen }
Character { id, name, avatar {body, hair, face, outfit, color}, ownerSessionId|'cpu', era, route, routeHistory[], position, money, debt,
            stats {int, str, charm, luck}, job {id, rank, exp}, education, military,
            love {partnerId, affection}, spouse {id, rank, trait, salary}, children[{trait, talent, stage}],
            house {id, price, value}, houseSwaps,
            cards[], items[], treasures[], history[], finished, goalBonus }
turn { order: [charId], currentIndex, phase,
       pending: { promptId, forCharacterIds: [..], options[], answers: {charId: optionId}, deadlineAt } }
bets { [turnNo]: { [charId]: { kind:'oddEven'|'range', pick, amount } } }
news { current: newsId }        // 시대 뉴스 속보
```

- `pending.forCharacterIds`가 1명이면 일반 결정, 여러 명이면 **동시 입력 페이즈**(명절 잔치·훈수 베팅·수능 퀴즈·경매·투표가 모두 이 구조를 재사용). `deadlineAt` 경과 시 서버 타이머가 `timeout` 액션을 디스패치해 미응답자는 기본 선택으로 처리. 엔진은 순수 함수를 유지(타이머는 라우트 계층).
- 이모지 리액션·채팅은 엔진 상태가 아닌 **SSE 브로드캐스트 전용**(`reaction` 이벤트)으로 처리.

- `eraTurns`: `eras.json`의 기본값(예: 아기 3, 초등 5, 중등 4, 고등 5, 청년 15, 중년 15, 노년 6)을 관리자가 방 생성 시 시대별로 덮어씀. 모드(kids/adult)는 포함 시대만 결정. 보드는 `board.json`의 칸 풀에서 시대별 턴 수에 맞게 생성(정지칸은 고정 위치 보장).
- 턴 상태기계: `awaitSpin → resolveSpace → (awaitDecision)* → endTurn → 다음 캐릭터`.
- 액션: `spin`, `choose {optionId}`, `useCard {cardId}`, `buyItem`, 관리자 `start`, `end`.

## 루트 시스템 (성인 이후 3갈래)

원작은 성인 시대에 사랑/커리어 2갈래지만, 이 프로젝트는 **청년·중년 시대 각각의 시작에 있는 「루트 선택 칸」(정지칸)에서 3갈래 중 하나를 고른다**. 시대가 끝나면 합류 칸에서 다시 만나고, 다음 시대 시작에 다시 선택한다(청년에 연애, 중년에 부동산 같은 조합 가능). 노년 시대는 짧아서 단일 트랙 + 인생역전 서브맵.

| 루트 | 칸 구성(칸 풀 가중치) | 주요 이벤트 | 승리 자산원 |
|---|---|---|---|
| 💕 연애·육아 | 하트 칸 多, 이벤트 칸, 소액 급여 | 만남·데이트·프러포즈·결혼식·출산·돌잔치·자녀 성장, 소개팅, 명절 잔소리 | 배우자 맞벌이 급여, 축의금, 자녀 용돈 송금, 배우자 전용 급여 카드, 특별상(다복상·영재 부모상) |
| 💼 일·커리어 | 급여 칸 多, 직업 칸(랭크업 판정), 카드 칸 | 취업·전직·승진 시험·야근·회식·부상 리스크·공약 카드, 스타트업 투자 유치 | 급여·랭크업, 직업 전용 카드, 숨은 직업 해금, 특별상(커리어상) |
| 💰 보물사냥·부동산·금전 | 보물 칸, 매물 칸, 상점, 손실 칸(리스크), 럭키 칸 | 보물 발견(고려청자·옛날 동전·아이돌 굿즈…), 청약·매물 갈아타기·경매, 코인/주식 투자, 로또, 세무조사 | 집 자산가치, 보물 감정가, 투자 수익, 특별상(보물왕·건물주) |

- 각 루트를 끝까지 완주하면 **루트 메달**을 받고 결과발표 특별상 후보가 된다. 세 루트를 모두 경험하면 “인생 만렙” 칭호.
- 보드 생성: `board.json`의 시대별 칸 풀에 루트별 가중치(`routePools.love/career/money`)를 두고, `eraTurns`에 맞춰 루트별 트랙 길이를 동일하게 생성(어느 루트를 골라도 시대 종료 타이밍이 같음).
- 3D 표현: 루트 선택 칸에서 트랙이 세 갈래 색(분홍/파랑/금색) 리본으로 갈라졌다가 합류(목업 1 참조). 루트 라벨이 트랙 위에 떠 있고, 선택 시 카메라가 세 갈래를 훑는 연출.
- CPU는 능력치·자산 상황에 따라 루트 선택(매력 높으면 연애, 지력 높으면 커리어, 현금 많으면 부동산).
- 데이터: `character.route` (현재 루트), `character.routeHistory[]`, `board.eras[i].routes[key].tiles[]`.

## AI 에셋 파이프라인 (Gemini Nano Banana)

사용자 결정: 모든 그래픽 에셋을 이 프로젝트에서 Gemini API로 생성한다. 사용자는 Google Gemini API 키를 보유. 이 세션에서 `generativelanguage.googleapis.com` 접근이 되므로 구현 중 `GEMINI_API_KEY`를 환경변수로 받으면 바로 생성·커밋 가능(키 자체는 절대 커밋하지 않음).

**구성**
- `server/assets/gemini.js`: `@google/genai`로 이미지 생성 호출. 기본 모델 `gemini-2.5-flash-image`(Nano Banana), `config.json`에서 모델 ID 변경 가능. 텍스트 프롬프트 + 참조 이미지(base64 inline)를 함께 보내 **스타일·캐릭터 일관성** 유지. 키는 서버 환경변수 또는 관리자 페이지 입력 → `data/secrets.json`(gitignore)에 저장, 브라우저로는 절대 내려보내지 않음.
- `server/assets/manifest.json`: 필요한 에셋 전체 목록. 항목마다 `id, kind, size, promptTemplate, refs[], output, postprocess`.
- `server/assets/postprocess.js`(`sharp`, ARM64 프리빌드 있음): 리사이즈, 마젠타(#FF00FF) 배경 크로마키 → 투명 PNG, 트리밍, 2x/1x 변형, 스프라이트 시트 합치기, WebP 변환.
- `scripts/gen-assets.js`: CLI로 매니페스트 전체/일부를 배치 생성(구현 세션에서 사용). 관리자 페이지 **에셋 스튜디오**는 같은 모듈을 UI로 감쌈: 항목 선택 → 변형 4장 생성 → 미리보기 → 채택/재생성 → `public/assets/generated/`에 저장 + 매니페스트 상태 갱신. 수동 업로드로 교체도 가능.
- 비용·안전장치: 항목별 캐시(이미 채택된 에셋은 재생성 안 함), 동시 요청 2개 제한, 실패 시 재시도 3회, 일일 생성 한도 설정.

**에셋 종류와 생성 전략**

| 종류 | 내용 | 방식 |
|---|---|---|
| 스타일 앵커 | 1장. “한국 애니메이션풍 치비 캐릭터 + 밝은 셀 셰이딩 배경” 기준 이미지 | 가장 먼저 생성해 사용자가 고른 뒤, 이후 모든 생성의 참조 이미지로 첨부 |
| 2D 캐릭터 레이어 | 베이스 체형 2 × 피부 4, 머리 8×색 6, 눈 4, 표정 7종, 의상(아기·초등·중고등 교복·직업 17·한복·웨딩), 액세서리 6 | 같은 포즈·같은 캔버스(1024×1536)·마젠타 배경으로 레이어별 생성 → 크로마키 → 브라우저 캔버스에서 합성. 캐릭터 커스터마이징·컷인·초상화 모두 이 레이어 사용 |

**일관성 유지 규칙**: 프롬프트 = 스타일 바이블(고정 문구) + 항목 프롬프트 + 참조 이미지(앵커, 캐릭터 레이어는 해당 베이스 이미지). 캐릭터 레이어는 “이 이미지와 같은 캐릭터·포즈·크기·조명에서 X만 바꿔라” 형식으로 편집 모드 생성. 결과는 매니페스트에 프롬프트·시드·모델을 기록해 재현 가능.

**사전 테스트 결과 (이 세션에서 실제 생성, `scratchpad/mock/gen/`)** — 6장 생성 전부 성공, 장당 4~9초.
- 스타일 앵커(산길의 교복 커플)가 사용자 참고 이미지 분위기와 일치. 앵커를 참조 이미지로 넣은 배경(웨딩홀)·캐릭터 생성이 같은 화풍으로 나옴.
- 캐릭터 일관성: 마젠타 배경 베이스 캐릭터를 참조로 “의상을 의사 가운으로, 표정을 울음으로” 편집 요청 → 얼굴·머리·포즈·크기가 그대로 유지됨. 레이어 생성 전략이 유효.
- 크로마키: 모델이 정확한 #FF00FF를 내지 않음(실측 약 rgb(213,37,136)) → **모서리 샘플링 색 + 색상(hue) 기반 키**로 처리. “그림자 없음”을 요청해도 발밑 그림자를 그리는 경우가 있어 hue 키로 제거. 잔여 얼룩은 후처리에서 **작은 연결 성분 제거**를 추가한다.
- 아이콘 시트: 12개가 나오지만 그리드 정렬이 불규칙 → 아이콘은 **개별 생성(1:1, 흰 배경)** 또는 셀 테두리를 그리게 한 뒤 슬라이스. 시임리스 잔디 텍스처는 양호.
- 합성 검증: 생성 배경 + 키 처리 캐릭터 + 프레임/대사 상자로 만든 컷인(`mock-4-cutin-generated.png`)이 목표 룩에 도달. 이 화면 구성이 실제 `cutin2d.js`의 기준.
- 보안: 테스트에 쓴 키는 채팅에 노출되었으므로 사용자가 **재발급(회전)** 후 환경변수로 제공. 저장소에는 키를 기록하지 않음.

**움직이는 에셋 (애니메이션) 전략** — 사용자 질문에 대한 검증 결과와 채택안.
- 테스트: 베이스 캐릭터 1장을 참조로 “포즈만 바꿔라” 편집을 프레임별로 4회 호출(웅크림→점프→최고점→착지) → 크로마키 → `sharp`의 `join: { animated: true }`로 GIF/WebP 조립. 결과 `scratchpad/mock/gen/anim-jump.gif`. 캐릭터 동일성은 유지되나 프레임마다 크기·위치가 조금씩 흔들림 → 후처리에서 **바운딩 박스 기준 정규화(발끝 앵커·키 높이 맞춤)** 필요.
- 채택안(3단계 혼합):
  1. **키포즈 + 프로시저럴(기본, 전 캐릭터)**: 캐릭터 베이스당 키포즈 6종(대기·손흔들기·점프·환호·울기·놀람)을 생성하고, 브라우저에서 스쿼시&스트레치·바운스·흔들림·크로스페이드·표정 레이어 교체(깜빡임·입모양)·파티클로 움직임을 만든다. 호출 수 적고 일관성 좋음. 원작 컷인(정지 일러 + 소폭 움직임) 이상.
  2. **프레임 스프라이트(대표 동작만)**: 점프·환호·울기·걷기 등 4~5개 동작을 6~8프레임 per-frame 편집 생성 → 정규화 → 스프라이트 시트(WebP). 컷인의 하이라이트 순간과 결과발표 시상대에서 사용. 베이스당 약 30~40회 호출.
  3. **Veo 영상(선택, 특별 연출만)**: Veo 3.1 Fast 기준 약 $0.10/초, Lite $0.05/초 → 8초 클립 $0.4~0.8. 투명 배경 불가·커스터마이징 캐릭터 반영 불가이므로 오프닝·결혼식·엔딩 같은 고정 연출 3~5개에만 후순위로 검토.
- 3D 말판의 말·룰렛·카메라·파티클은 프로시저럴 애니메이션(Three.js)으로 이미 계획됨. 배경 일러스트는 하늘/중경/전경을 따로 생성해 **패럴랙스 + 흔들림**으로 살아 있게 한다(호출 3회/장소).
- 매니페스트에 `kind: 'pose' | 'sprite'`와 `frames`, `anchor` 필드를 추가하고, 후처리에 프레임 정규화·시트 조립·애니메이션 WebP 출력을 넣는다.

**단계**: 구현 순서 3단계(3D 보드·컷인) 직전에 “에셋 스튜디오 + 스타일 앵커 + 캐릭터 레이어 최소 세트”를 먼저 만들어, 이후 화면 작업이 실제 에셋으로 진행되게 한다. 에셋이 아직 없는 항목은 지금 목업의 SVG/프리미티브 자리표시자를 자동 사용.

## 캐릭터 커스터마이징 & 이벤트 컷인 (원작 방식)

**커스터마이징(로비)** — 원작처럼 파츠 조합, 조작은 단순하게(좌우 화살표로 넘김).
- 파츠: 성별 체형 2 / 피부색 4 / 머리 모양 8 + 머리색 6 / 눈 4 / 안경·모자 등 액세서리 6 / 기본 의상 6 + 색 6. 정의는 `avatars.json`.
- 3D 미리보기(회전) + 같은 파츠 정의로 2D 초상화를 캔버스에 합성(HUD·로그·모바일에서 사용).
- 랜덤 버튼, 이름 입력. 캐릭터 8개까지 각각 다른 외형.
- **성장이 외형에 반영**: 시대별 자동 의상 교체(아기 배냇저고리 → 초등 체육복 → 중고등 교복 → 청년 직업 유니폼(의사 가운·경찰 제복·유니폼·정장·아이돌 무대의상 등) → 노년 한복/개량한복 + 흰머리). 결혼 시 반지, 반려동물 획득 시 옆에 동행 모델.

**이벤트 컷인(2D, 원작 방식)** — 말판은 3D, 이벤트는 **2D 일러스트 화면**으로 전환한다(목업 2·3 참조).
- 구도: 색 패턴 프레임 → 가로형 일러스트 창(배경 일러스트 + 2D 캐릭터) → 노란 테두리 대사 상자(▼로 넘김) → 하단 캐릭터 탭·버튼. 모바일은 같은 구도를 세로로 쌓고 일러스트 창을 16:9로 유지.
- **2D 캐릭터**: 로비에서 고른 파츠 정의(`avatars.json`)를 **Gemini로 생성한 PNG 레이어**(머리·앞머리·눈·입·볼·몸·의상·액세서리)로 캔버스 합성. 시대·직업별 의상(교복·정장·가운·한복)과 표정 세트(기쁨·눈물·놀람·분노·땀·하트·부끄러움)를 레이어 교체로 표현. 3D 말과 같은 파츠 정의를 공유하므로 커스터마이징 한 번으로 둘 다 반영. 레이어가 아직 없으면 목업의 SVG 자리표시자 사용.
- **배경 일러스트**: 장소별 Gemini 생성 PNG(학교·산길·웨딩홀·회사·병원·사찰·아파트·고향집·제주도·로또방 등). `public/assets/generated/bg/<scene>.png`를 교체하면 그림이 바뀌는 드롭인 구조.
- **프레임 테마 = 이벤트 톤**: 프레임 색·패턴은 고정이 아니라 `events.json`의 `tone`으로 결정. 연애·육아=분홍, 일·커리어=파랑, 보물·부동산=금색, 좋은 일=초록, 나쁜 일=남색, 명절=빨강, 결과발표=보라. 대사 상자 테두리·태그 색도 같이 바뀌고, 톤별 효과음(팡파레/둥-/하트)도 매칭.
- **표정 팝업**: 이벤트 결과에 따라 머리 위 이모티콘(`emotion`: `joy|cry|angry|sweat|love|shock`). 엔진 events에 `emotion`·`tone`·`scene` 필드 부여.
- **말풍선 대사**: `lines.json`에서 상황 태그(급여·파산·결혼·야근·수능…)별 반말 드립 대사를 랜덤 선택(시드 기반이라 전원 동일 대사). 캐릭터별 짧은 감탄사 효과음(앗싸/헐)을 함께 재생.
- 결혼·출산·만남 등 2인 이상 이벤트는 배우자·자녀·상대 캐릭터도 같은 일러스트 창에 등장. 다른 플레이어의 이모지 리액션이 창 아래에 실시간 표시.
- 컷인은 순수 HTML/SVG/CSS라 WebGL 없이도 동작 → 저사양·TV 모드에서도 동일 품질.

## 그래픽 (Three.js)

- **보드**: 시대별 트랙을 곡선 경로(CatmullRom)로 마을 위에 배치, 칸은 도로 위 사각 타일(타입별 색·아이콘, 원작 참고). 룰렛은 원작처럼 화면 한쪽에 큰 원판 오버레이(1~10 색 분할, 공을 당겨 돌리는 연출, 결과 숫자 강조). 시대마다 배경 색·소품(초등학교 운동장, 대학 캠퍼스, 아파트 단지, 사찰, 제주도 등)을 프리미티브 조합으로 표현.
- **말(캐릭터)**: 로비에서 고른 아바타 파츠(머리 모양·피부·옷 색)를 박스/구/실린더 조합 로우폴리 인형으로 생성. `public/assets/models/*.glb`가 있으면 GLTFLoader로 교체 로드(무료 CC0 에셋 드롭인 가능).
- **연출**: 룰렛 3D 회전 → 말이 칸 단위로 점프 이동(카메라 팔로우) → 칸 도착 시 코인·하트·별 파티클. 애니메이션은 클라이언트 `animator.js`가 서버 events 큐를 순차 재생하며, 재생 중 도착한 새 상태는 큐 뒤에 붙임.
- **성능 대응**: 모바일·저사양은 픽셀비 제한, 그림자 off, 파티클 수 축소. 설정에서 **2D 간이 보드 모드** 토글(WebGL 미지원 브라우저 폴백).

### 라즈베리파이 4 그래픽 가능 범위 (조사 결과)

- **서버 역할만 할 때**: 3D 렌더링은 전부 접속한 폰·PC 브라우저가 담당. 라즈베리파이는 정적 파일·JSON·SSE만 처리하므로 그래픽 수준과 무관하게 부담 없음. 이것이 기본 구성.
- **라즈베리파이를 TV 화면(클라이언트)으로도 쓸 때**: VideoCore VI는 OpenGL ES 3.1을 지원해 Chromium에서 WebGL2 하드웨어 가속이 됨(Raspberry Pi OS Bookworm 기본). 실측 보고는 1080p 중간 규모 데모에서 17~27fps, 가속이 꺼진 상태에서는 4~5fps. 즉 **로우폴리·저부하 씬이면 30fps 근처 가능, 화려한 씬은 불가**.
- 따라서 3D 씬은 처음부터 다음 예산 안에서 설계한다:
  - 드로우콜 100 이하(타일·소품은 `InstancedMesh`/지오메트리 병합), 삼각형 5만 이하.
  - 그림자·포스트프로세싱·안티앨리어싱 없음, `pixelRatio` 1 고정, 조명은 Hemisphere + Directional 1개.
  - 텍스처 대신 버텍스 컬러/단색 머티리얼(`MeshLambertMaterial`).
  - **“TV 모드” 프리셋**: 720p로 렌더 후 CSS로 확대, 파티클 off, 카메라 고정 조감 시점. `?quality=low` 또는 설정 토글로 켬. Chromium 키오스크 실행 시 `--ignore-gpu-blocklist --enable-gpu-rasterization` 플래그를 README에 안내.
  - 그래도 부족하면 2D 간이 보드 모드로 자동 전환(첫 3초 평균 fps < 15 감지 시 안내).

## 사운드

- `audio.js`: Web Audio API로 효과음 합성(룰렛 틱, 코인, 결혼 팡파레, 부상 효과음, 골 팡파레)해 에셋 파일 없이 동작. `public/assets/audio/`에 mp3/ogg가 있으면 파일 우선 사용(시대별 BGM `bgm_<era>.mp3`, 효과음 `sfx_<name>.mp3`).
- 모바일 자동재생 정책 대응: 첫 터치 시 AudioContext resume. 음소거·볼륨은 `localStorage`에 저장.

## 화면 구성 (모바일 반응형)

**게임 페이지 `/`**
1. 입장: 방 코드 + 이름.
2. 로비: 내 캐릭터 생성(이름, 아바타 파츠) 최대 남은 슬롯까지, 3D 미리보기. 참가자·캐릭터 목록 실시간 표시.
3. 게임: 상단 3D 보드(전체 폭), 하단 HUD. 데스크톱은 우측 사이드 패널(캐릭터 탭: 돈·능력치·직업·가족·카드), 모바일(≤768px)은 하단 시트로 접었다 펼침. 룰렛 버튼은 내 캐릭터 차례일 때만 활성, 결정 모달은 전체 화면 시트. 터치 드래그로 카메라 회전, 핀치 줌.
4. 결과: 골 순서 → 보물감정 연출 → 특별상 → 총자산 순위(3D 시상대).

**관리자 페이지 `/admin`** (1차)
- 비밀번호 로그인.
- 방 생성: 모드, **시대별 턴 수(기본값 표시, 개별 수정)**, 최대 캐릭터 수, 초기 자금, CPU 허용 → 방 코드 발급.
- 방 목록(상태, 접속자, 캐릭터 수), 로비 상세, 게임 시작(캐릭터 ≥2 검증), 강제 종료, 삭제.
- 이후 확장 예약: 캐릭터 배정 변경, 상태 개입(턴 넘기기/돈 수정/undo), 룰 JSON 편집·리로드.

## 구현 순서 (10단계 로드맵)

각 단계는 독립적으로 검증 가능한 산출물(테스트 통과 + 실행 가능한 화면)을 남기고, 단계마다 별도 커밋으로 기록한다. 개발은 단계별로 Opus 에이전트가 수행하고, 오케스트레이터가 검증·커밋한다.

## 검증 방법

- **단위 테스트** (`node --test`): 룰렛 범위, 시대별 턴 수 반영·시대 전환, 돈 칸 정산, 취업·랭크업(시드 고정), 결혼 흐름, 부동산 1인 1채·갈아타기 보상판매·매물당 1명 제한, 자녀 용돈 송금 계산, 숨은 직업 해금 조건, 결과 정산 합계, 소유권 검증(남의 캐릭터 액션 거부), 관리자 eraTurns 유효성, 가문 턴 순서, 동시 입력 페이즈 타임아웃 기본 처리, 훈수 베팅 정산, 거래 제안/수락/거절, 칭호 조건 판정, 3루트 트랙 길이 동일·합류 위치 일치·루트 메달 부여.
- **시뮬레이션** (`node scripts/simulate.js --games 200`): 랜덤 결정 풀 게임 반복. 예외 0건, 턴 수·평균 자산·직업 분포 출력으로 밸런스 확인.
- **API 스모크**: curl로 방 생성 → 2세션 입장 → 캐릭터 8개 → 시작 → spin/choose 반복 → finished.
- **브라우저 E2E** (Playwright 헤드리스, 사전 설치된 Chromium): A가 1~4번, B가 5~8번 조종. 한쪽 행동 시 반대쪽이 SSE로 즉시 갱신, 새로고침 후 세션 복원, 서버 재시작 후 방 복원, 3D 씬 렌더 오류 없음(콘솔 에러 0), 모바일 뷰포트(390×844)에서 HUD·모달·컷인 레이아웃 스크린샷 확인, 커스터마이징 파츠 변경이 3D 말·초상화·컷인에 반영, 이모지 리액션이 상대 화면에 표시, 훈수 베팅 결과 정산, 단체 사진 PNG 다운로드.
- **에셋 파이프라인**: 매니페스트 스키마 검증 테스트, 후처리 단위 테스트(마젠타 크로마키 → 투명 PNG, 시트 슬라이스 개수), Gemini 클라이언트는 목(mock) 응답으로 테스트하고 실제 키가 있으면 `scripts/gen-assets.js --only style-anchor`로 1장 생성 후 파일 존재·크기 확인. 관리자 에셋 스튜디오에서 생성→채택→게임 화면 반영을 브라우저로 확인. 키가 응답·로그·저장소에 노출되지 않는지 grep.
- **라즈베리파이**: `npm install --omit=dev && npm start`, 서버 메모리 100MB 이하, systemd 자동 시작, 휴대폰 브라우저에서 3D 보드 30fps 이상(안 되면 2D 폴백 안내), `sharp` ARM64 설치 확인.

## MC NPC — 호야 & 봄이 (5.6단계, 5.5 완료 후)

원작의 진행 MC 2인 역할을 사용자의 반려견 두 마리(시츄)가 맡는다. 사진 원본은 `data/mc-refs/`(gitignore)에만 두고, 저장소에는 사진을 참고해 생성한 일러스트만 커밋한다.

| | 호야 (`hoya`) | 봄이 (`bomi`) |
|---|---|---|
| 외모 | 거의 흰 털, 갈색·검정 귀, 눈가 연갈색, 혀를 살짝 내민 얼굴 | 흑백 얼룩, 눈 주변 검은 무늬, 이마 흰 줄, 흰 주둥이·가슴, 검은 점박이 앞발 |
| 관계 | 남자아이, 봄이의 오빠 (봄이를 「봄이야」라고 부름) | 여자아이, 호야의 여동생 (「오빠」·「호야 오빠」라고 부름) |
| 역할 | 리액션·분위기 담당 | 진행·해설 담당 |
| 성격 | 해맑은 장난꾸러기, 먹을 것에 약함 | 시크한 츤데레, 표정 변화 적고 가끔 한마디가 웃김 |
| 말투 | 반말, "~멍!", 감탄사 많음 | 짧은 존댓말 "…그렇습니다", 가끔 "흥" |

- **데이터**: `server/data/mc.json`(프로필·색·표정 목록), `lines.json`에 MC 대사 풀(`mc.<상황>.<hoya|bomi>`): 게임 시작 인사, 첫 룰렛 안내, 시대 전환, 루트 선택, 큰 이벤트(결혼·취업·파산·보물), 골인, 훈수 베팅 적중, 기초연금, 결과 발표 진행, 벌칙 발표. 두 MC가 주고받는 만담(2~3줄 대화)도 포함.
- **엔진**: `presentation.js`가 해당 이벤트에 `mc: [{speaker, line, expression}]`를 결정적으로 부여(같은 서브 RNG 규칙, 전원 동일).
- **연출**: 컷인 우측 하단에 MC가 작게 등장해 말풍선으로 한마디(과하지 않게, 큰 이벤트 위주·연속 등장 쿨다운). 시대 전환과 결과 발표는 두 MC가 화면 중앙에 나오는 **MC 컷인**(방송 스튜디오 배경). 3D 말판에서는 룰렛 옆에 로우폴리 강아지 2마리 마스코트(꼬리 흔들기, 이벤트 리액션). 로비에서 두 MC가 환영 인사.
- **에셋**: 사진을 참조 이미지로 Gemini 생성 — MC별 기본 + 표정 6(기쁨·놀람·슬픔·화남·자신만만·졸림) + 포즈 3(손 흔들기·박수·마이크 들기), 듀오 컷 1, 방송 스튜디오 배경 1. 크레딧 충전 전에는 SVG 치비 강아지 자리표시자.
- **설정**: 관리자 방 설정에 MC 등장 빈도(많이/보통/적게/끄기).
